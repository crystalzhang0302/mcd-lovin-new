# 唯新才能解腻 🍟

> 麦当劳新品货架 —— 把「今天有什么新品、在哪家店、多少钱、有什么连带活动」做成一张点开就能逛的卡通货架。
>
> **非麦当劳官方产品**，基于麦当劳开放 MCP 能力独立开发，为「1024 程序员节 · 麦当劳程序员创意开发大赛（M-CODE）」参赛作品。

**🚀 在线体验：https://crystalzhang0302.github.io/mcd-lovin-new/**（手机可直接打开，11 个城市随点随切）

![screenshots](out/v3_home.png)

## 这是什么

「上新」信息散落在 App 的各个角落：菜单里的一个小角标、活动日历里的一行字、不同城市的门店还各有差异。本项目用麦当劳 MCP 把它们拧成一件事：

**选个城市 → 首页罗列该城全部新品 → 点开看详情（门店 / 价格 / 祝福签）→ 选一家店直接生成下单凭证。**

### 功能

| 功能 | 说明 |
|---|---|
| 新品货架 | 首页 2 列卡片网格，展示当日候选池全部食品类新品（周边商品自动剔除） |
| 城市切换 | 内置 11 城数据包（上海 / 北京 / 广州 / 深圳 / 成都 / 杭州 / 南京 / 武汉 / 重庆 / 西安 / 嘉兴），一键切换，记住你的选择 |
| 热度排序 | 点开详情即计入热度，按「点的人多」重排，附上新时间 / 价格 / 距离排序 |
| 详情弹层 | 吉祥物送出一句祝福签 + 商品介绍 + 官方连带活动卡（联名 / 限时 / 回归） |
| 门店列表 | 每个新品列出该城 5 家门店的在售状态、距离、实测价格 |
| 下单凭证 | 选门店 + 数量，生成可直接执行的 `create-order` 指令，一键复制交 MCP AI 助手即真实下单 |
| 时段实况 | 数据每天 7:00（早餐）与 10:35（正餐）各实测一轮，货架反映当前餐段真实在售情况 |
| 离线演示 | 内置真实抓取数据，无需 Token 也能完整体验 |

### 一个真实的发现

「上新」并不是全国一致的：11 城实测，约七成新品全国同步，约三成存在区域差异——三文鱼双虾至尊月堡、咸蛋黄鸡腿蛋月堡只在部分城市上架，玫瑰红糖糍粑风味派偏西南，酥酥多笋卷偏华东。**你看到的货架就是你那家店的新品组合**，切换城市亲手验证，这正是这个工具存在的理由。

## 安装与运行

零依赖，纯静态页面 + Python 标准库脚本。

```bash
# 1. 体验（离线模式，无需任何配置）
#    直接用浏览器打开 index.html，或访问上面的在线地址

# 2. 抓取数据（需要麦当劳 MCP Token）
export MCD_MCP_TOKEN=你的Token        # 也可配置在 ~/.workbuddy/mcp.json

python fetch_all.py                   # 按 cities.json 批量抓全部城市（约 5 分钟）
python build_all.py                   # 构建全部城市数据包 + manifest
# 刷新 index.html，货架即为最新数据
```

**加城市 / 换锚点**：编辑 `cities.json`，加一行 `{"slug": "suzhou", "name": "苏州", "city": "苏州市", "keyword": "观前街"}`，重跑上面两条命令即可，前端切换器自动跟随，无需改任何代码。

单城调试也可以：

```bash
python fetch_all.py --only chengdu    # 只补抓某个城市
python build_site.py                  # 只重建默认城市（上海）的数据包
```

> ⚠️ 本仓库不含任何 Token / 密钥。Token 只从环境变量 `MCD_MCP_TOKEN` 或本地 `~/.workbuddy/mcp.json` 读取。

```text
打开线上地址（或本地 index.html）

```

## 目标用户

- **尝鲜族**：想第一时间吃到新品，但不想每天翻 App 找角标的人
- **选择困难户**：新品太多不知道挑哪个，需要价格 / 距离 / 活动一起看
- **麦门考据党**：关心「我这家店有没有」「和别家差在哪」的区域差异观察者

## 项目结构

```text
index.html            # 单文件 H5（零依赖，内嵌离线兜底数据 + 城市切换器）
cities.json           # 城市配置包：增删城市 / 换锚点只改这个文件
fetch_pool.py         # 抓单个门店候选池（query-meals → calculate-price）
fetch_matrix.py       # 抓多门店新品矩阵（5 家店交叉比对）
fetch_all.py          # 按 cities.json 批量抓全部城市
build_site.py         # 合并候选池 + 门店矩阵 + 文案资产 → 单城数据包
build_all.py          # 构建全部城市数据包 + data/cities/manifest.js
data/cities/          # 每城一份数据包（pool / matrix 中间产物 + 构建产物 js）
data/copy.json        # 人工维护的祝福签 / 介绍文案资产（按名称归一化匹配）
out/                  # 界面截图
```

## 数据更新机制

- **每天两次**：7:00（早餐时段）与 10:35（正餐时段）各实测一轮 11 城，自动构建并推送本仓库，GitHub Pages 数秒内同步
- 早餐时段正餐新品不上架属正常现象，货架如实反映「此刻去店能买到什么」
- 每份门店数据都带实测时间戳，未经当餐时段实测的组合会标注「时段校验」，不冒充实测

## 已知边界（诚实声明）

- **下单凭证不是支付链接**：`create-order` 是服务端能力，静态网页不能存放用户 Token。凭证 + MCP AI 助手 = 真实下单；接后端代理后可直接返回官方支付链接。
- **热度目前是本机计数**：跨用户热度榜需要云端计数服务，数据结构已预留。
- **定位是城市级而非街道级**：当前按预设锚点商圈实测，浏览器定位 + 实时查询需要后端代理托管 Token，属规划中的赛后迭代。
- 营养数据：官方营养接口为静态清单，不覆盖当期新品，故本项目不提供卡路里维度，避免编造数据。
